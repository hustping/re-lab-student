本题全班23名同学全部解决，难度较低，总结如下：
一、涉及技术总结

本题是授权教学环境下的软件分析课程案例，核心是理解一个桌面程序的授权状态机与信任边界，而非提供任何可操作的风险方法。

1. 文件格式识别
通过 PE 资源、版本信息识别 Inno Setup 安装包；通过 FontKit.exe 与 _internal/ 目录判断主程序为 PyInstaller onedir 打包。

2. 归档解析
使用 PyInstaller 自带 CArchiveReader 读取归档目录；针对 PYZ 归档，结合 PYZ\0 头部、pyc magic 与 zlib 流特征定位模块，提取 license_manager 等业务代码。

3. 字节码分析
用 xdis / pydisasm 在 Python 3.13 下反汇编 Python 3.11 字节码，通过 LOAD_CONST、LOAD_GLOBAL、调用顺序还原常量、函数结构与源码级逻辑。

4. 授权逻辑分析
程序维护 Free/Pro 状态机：读取本地授权缓存、校验完整性、绑定机器指纹、判断有效期、按需联网验证。涉及 sha256 截断校验、注册表 MachineGuid 哈希、HMAC 响应校验、7 天免联网窗口、30 天离线宽限等。

5. 取证与验证
用 SHA256 做文件同一性比对；用 winreg 读取机器指纹；用 ctypes 与 Pillow 做窗口枚举、置前、DPI 换算和截图取证；通过程序运行结果验证授权状态变化。

6. AI 辅助与独立复验
AI 用于解释字节码、梳理逻辑、提示常量；所有结论均需用独立手段复验，如重新下载比对哈希、自行重算校验值、以程序运行结果确认。

二、建议优化思路

本题暴露的根本问题是：客户端被当作可信执行环境，本地凭证可自行生成并自行验证。正确优化应从信任根转移开始。

1. 非对称签名替代对称校验
服务端用私钥签名授权令牌，客户端仅内置公钥验签。公钥公开无妨，私钥不出服务端，避免密钥硬编码。

2. 短有效期令牌与吊销机制
将授权令牌有效期缩短，例如 24 小时，到期必须联网续期；服务端维护吊销列表，可实时拒绝已失效授权。

3. 关键功能云端化
本地只保留界面与轻量逻辑，真正有价值的 Pro 功能通过服务端 API 执行。服务端拒绝服务即可控制授权，不依赖客户端自律。

4. 收敛离线宽限
减少或取消长期免联网窗口，改为“短令牌 + 定期续期”；离线宽限仅作为网络异常时的临时措施，并记录审计。

5. 机器绑定纳入签名载荷
将机器指纹、授权码、到期时间等一起签名，服务端签发时绑定，客户端无法单独修改任一字段。

6. 密钥与配置管理
密钥、盐、产品常量不应作为安全依据；客户端只保存公钥与公开参数，敏感逻辑全部服务端化。

7. 客户端完整性校验与强制更新
作为辅助手段，可增加自校验、版本强制更新，提高分析成本，但不能替代服务端权威。

8. 安全设计原则
坚持“客户端不可信”、纵深防御、最小权限、可观测审计。授权系统的权威性必须来自服务端，而非本地文件或硬编码常量。
